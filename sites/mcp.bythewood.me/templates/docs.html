Signing in

oauth through auth
  1. Claude opens a browser on auth.bythewood.me, which asks for a fresh six digit code from your phone.
  2. auth asks whether to let the connector read orchard. Allowing makes a session just for it, good for 90 days.
  3. Claude gets a token for an hour at a time and swaps it for a new one quietly. It reads every tool as that session.

Revoke the connector's session on auth's sessions page and its next call is refused. Only Claude's own clients, claude.ai and Claude Code, can start a sign in. Untick gate:write on auth's consent page to connect one that only reads, and gate_propose and gate_edit are then refused.

Approving tools

always allow

Claude asks before it uses each tool, and lets you always allow one. Every tool marked read only below sets readOnlyHint and can't change a thing, so always allow is safe for those. gate_propose only adds a gate rule that watches until you turn it on, so letting it ask each time costs little. gate_edit changes a rule live and sets destructiveHint, so keep it asking.

What's kept

{{.Keep}} days

Every request with the connector that made it, the tool and its arguments, how long it took, whether it failed, the request's JSON-RPC id and error code, and the first 600 characters of the answer. The raw view on calls is rebuilt from those, so it never shows more than that. The same line goes to logging.bythewood.me as source mcp. Tokens are kept hashed, and the session auth handed over is the one secret stored as it is, since it has to be sent on to each tool.
