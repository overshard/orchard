gate · docs

Rules in lines, live on save.

Caddy asks gate about every request before a site sees it. Here's how a rule is written and what gate does with it.

Writing a rule

one condition a line

Each line is a field, a test and the values, and every line has to hold. Any one of the values on a line is enough, and not in front flips the line.

host is auth.bythewood.me
path is /login /code /recovery
not country is US

Fields

host
the hostname asked for
path
the path, without the query
query
everything after the ?
method
GET, POST and the rest
ip
addresses or ranges, ip is 203.0.113.0/24, only takes is
asn
the network's AS number, asn is 14061 AS16509
country
two letters, from DB-IP, with Cloudflare's guess when DB-IP has none
ua
the user agent
crawler
a checked crawler's name (google, bing, duckduckgo, apple, yandex, baidu, openai, anthropic, perplexity, ccbot, amazon, mistral, meta), fake when the user agent claims one and the address isn't theirs, preview for a link preview, or none
header:Name
any request header, header:Accept-Language is with nothing sent is empty

Tests

is
equals one of the values
prefix
starts with one of them
contains
has one of them anywhere
suffix
ends with one of them
regex
the rest of the line is one Go regex, add (?i) to ignore case

Crawlers are checked against the ranges each owner publishes, fetched daily, then reverse DNS that resolves back for Bing, Yandex, Baidu, Apple, Amazon and Common Crawl, and Meta's own network. Everything but regex ignores case. A field gate doesn't know, like the country of an address no database has, fails its line either way, so not country is US never catches an address with no country.

What a rule does

in this order
allow
lets it through and stops looking, so nothing below can refuse it
block
answers 403 or 404 with the message, and nothing reaches the site
limit
lets an address through so many times a minute, then answers 429
challenge
sends the proof of work page unless the visitor already solved one on that host this week

A watching rule runs, counts and samples what it would have done, and doesn't act. Ban after counts one address's hits in ten minutes and bans it from every host for a while once it passes the number. Keep out of the access log is for noise like scanners, which gate still counts here.

Who never sees a rule

  • Requests from inside orchard, loopback and the box's own public address, set on the settings page.
  • Anyone signed in to orchard, asked of auth only once something would have refused them.
  • The challenge page's own /__gate/ routes.

When something goes wrong

Settings has a mode for only watching and one for off. If gate itself is down, Caddy can't ask, and every site answers 502 until it's back.

From an agent

the mcp connector
gate_report
the mode, the counts, every rule with its hits, who's being refused, bans and changes
gate_traffic
narrowed to a network, country, host, address, rule or verdict, with sampled requests
gate_propose
adds a rule that only watches and waits for you, and ends in 30 days unless it's turned on

Proposals show first on the overview with what they would have caught, and the tab's dot goes amber until you turn each on, keep it watching or dismiss it.

In Caddy

one snippet
handle /__gate/* {
  reverse_proxy orchard-gate:8000
}
forward_auth orchard-gate:8000 {
  uri /check
  header_up X-Gate-Ip {client_ip}
}

A 2xx lets the request on to the site, and anything else gate answers goes back to the visitor as it is.
