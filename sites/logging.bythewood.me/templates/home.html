v0.1.0 · alpha · self-hosted

The logs your own machines already wrote, finally read by something.

Every site here emits structured records with typed attributes and sends them to Docker's log driver, where they rotate away unread. This is the other end of that: an in-process shipper on each site, one ingest endpoint on the internal bridge, SQLite behind it, and graphs in front. Latency percentiles, status distributions, error rates and full text search over the raw lines, with hourly counters kept after those lines age out.

shipping
A handler, not a sidecar

Each site installs a slog.Handler that tees: stdout is written exactly as before, and a copy goes onto a bounded queue that a background goroutine flushes. Nothing blocks the caller, a full queue drops, and a failed POST drops. stdout stays the source of truth, so the worst outage here costs some lines on a dashboard.

addressing
No token, because no route

Sites post to a container name on the internal bridge, never over the tunnel, and the public hostname refuses /ingest outright. Anything able to reach the endpoint is already inside the network, so there is no shared secret to rotate and no new environment variable on any site.

storage
Raw lines and hourly counters

Records are batched into one writer and committed a few hundred at a time, with the hourly rollup written in the same transaction so the graphs can never disagree with the search. Raw lines expire on a schedule; the counters do not, which is what lets a year-long chart read a few hundred rows.

reading
Percentiles, not averages

p50, p95 and p99 computed from the actual distribution rather than interpolated, and paths ranked by p95 rather than mean, because the endpoint that is fast a thousand times and terrible twice is the one worth finding. Status classes, level mix, busiest paths and per component volume alongside.

signals
The absence of a header

Every request that crosses the tunnel carries a CF-Ray. A request log entry without one reached the origin directly, which is worth knowing and was already being recorded by every site here with nothing reading it. It is a tile on the dashboard.

stack
One Go binary and a file

Go, html/template, SQLite through a pure-Go driver, and a Vite bundle compiled into the executable. Typst renders the PDF report on the request path, which is the only reason the image is Alpine rather than empty. No agent, no collector daemon, no second process.
