If the repository is over 100 MB, seed it differently

Cloudflare refuses any single request body over 100 MB, and the tunnel hostname has to stay proxied, so nothing here can raise it. This only affects the first push of an existing repository: every push after that sends new objects only and is kilobytes. Check with git count-objects -vH and look at size-pack.

1. Seed over the Docker bridge, from a container on orchard-edge. Cloudflare is not in the path, so no limit applies:

git push http://{{.Bridge}}:8000/{{.Name}}.git --all && git push http://{{.Bridge}}:8000/{{.Name}}.git --tags

2. Or push in slices, which works from anywhere. Each slice is its own request, so none of them approaches the limit:

git log --oneline --reverse main | awk 'NR % 500 == 0' | cut -d' ' -f1 \
  | while read sha; do git push origin +$sha:refs/heads/main; done
git push origin main

Halve the step if a slice still fails. Raising http.postBuffer does not help: git's own documentation says it only disables chunked encoding for servers that cannot handle it.

Pushing a repository here

Any name works, and pushing to one that does not exist creates it. The username is ignored, so anything will do; the password is a push token from Settings.

git remote add origin {{.CloneURL}}/<name>.git
git push -u origin main
